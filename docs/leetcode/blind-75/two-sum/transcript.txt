Let’s consider the simplest way to solve this problem: check every possible pair of elements in the array and see if their sum equals the target. To do this, we use two nested for loops, examining each unique pair of indices. This method is called the brute force approach. Although it requires very little additional memory (O(1) space complexity), it’s not efficient for large arrays because it has a time complexity of O(n²)—since we might need to check nearly every pair.

Can we do better than O(n²) time? The answer is yes! By using a different strategy, we can bring the time complexity down to O(n). However, to achieve this faster speed, we must use extra memory (O(n) space complexity). This is a typical trade-off: faster algorithms often use more space. The most efficient solution for this problem uses both linear time and linear space. We'll now explore this approach in detail. A brute force approach is not ideal—let’s think about a more efficient way. Can we solve this problem in linear time, that is, by making only one pass through the array? Here’s how: as we go through each number from left to right, for every current element (let’s say 5), we want to know if there’s a value to its left that, when added to 5, equals the target (which is 9). In other words, we check if (9 - 5) = 4 has already been seen earlier in the array.

So as we visit each number, we keep track of which numbers we have already seen. If we see 2, then 1, then 3, and now 5, we ask: did we already see a 4? If so, we found a pair that sums to 9.

After checking, we also store 5 as a seen value and continue. Moving on to the next element, 8, we check if we’ve seen (9 - 8) = 1 before. In this case, yes, we have already seen 1. So, we’ve found our valid pair: 1 and 8.

However, the problem asks for the indices, not just the values. To get constant-time lookups and still know the indices, we shouldn’t just use a set—we should use a hash map (dictionary) that stores the value as the key and its corresponding index as the value. This way, when we find a match, we can immediately return the required indices.

To solve this problem efficiently, we need to store both the element values and their indices as we scan through the array. This is where a hash map (or dictionary) is extremely useful because it allows us to quickly check if a value we've seen earlier completes a pair that sums to the target.

Here's how the hash map approach works:

- We scan the array from left to right, examining each element and its index.
- For each current element, we calculate its complement: `complement = target - current_element`.
- We check if this complement already exists in the hash map.
    - If it does, we've found our answer! Since the hash map stores the index of the complement, we simply return both indices.
- If the complement isn't in the hash map, we add the current element and its index to the hash map for future lookups.

In summary, by storing each number along with its index in a hash map, and checking if the complement exists as we iterate, we can solve the Two Sum problem in linear time and space complexity.
